= 1.3.0 =
* Fixed: a site with no tracker URL loaded the placeholder https://analytics.example.com/script.js and recorded nothing, with no warning. The placeholder is no longer a default, and nothing is added to your pages until the website ID and tracker URL are both set.
* Fixed: a site that saved its settings while the placeholder was showing kept it as its tracker URL. A URL on an example domain now counts as not set, and the field shows empty so you can enter your real one.
* Added: an admin notice, "Umami Tracking is not recording any visits", until the website ID and tracker URL are set, with a link to the settings.
* Added: the plugin now updates itself from its GitHub releases, through the normal WordPress Updates screen.
* Removed: the GitHub Plugin URI header added in 1.2.2. Git Updater no longer manages this plugin, so the two updaters cannot both offer an update.
* Changed: the plugin now declares that it requires PHP 7.4 or later.

= 1.2.2 =
* Added GitHub Plugin URI header so updates can be delivered from GitHub via Git Updater (afragen/git-updater).
* Updated the donation link.

= 1.2.1 =
* Custom Event Tracking Script now detects up front when the account lacks the `unfiltered_html` capability (removed by some security plugins, or limited to Super Admins on Multisite): the field is shown read-only with a clear explanation, and a save that would be blocked now shows an error instead of silently discarding the change.
* Fixed the field placeholder that showed a full example script, which made an empty (unsaved) field look identical to a saved one. The example now lives below the field as copyable documentation.

= 1.2.0 =
* Added custom event tracking script setting - output your own JavaScript immediately after the Umami tag to capture custom events (e.g. listen for DOM events and call window.umami.track())
